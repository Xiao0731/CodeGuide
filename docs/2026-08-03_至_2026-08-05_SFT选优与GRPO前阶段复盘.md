# EXP-022：TACO-100 checkpoint 轨迹评测

**日期**：2026-08-04 至 2026-08-05  
**类型**：实验 / SFT checkpoint 轨迹  
**评测集**：冻结平衡 TACO-100  
**执行口径**：确定性生成、统一代码提取、本地 Docker 严格验证。

## 结果

| 模型 | Overall | Standard | Call | 平均测试通过率 | 平均生成长度 |
|---|---:|---:|---:|---:|---:|
| Base | 32% | 4% | 60% | 0.393958 | 462.69 |
| LR 2e-4 step50 | 42% | 26% | 58% | 0.519880 | 572.65 |
| LR 1e-4 step20 | 39% | 18% | 60% | 0.501760 | 613.14 |
| LR 1e-4 step200 | 40% | 26% | 54% | 0.536480 | 573.63 |

## 观察

- full adapter 末尾并不是所有模式的统一最优点；不同 I/O 模式存在不同训练阶段偏好。

- step200 的平均测试通过率最高，但严格 Pass@1 并非最高；说明部分题目的边界测试有所改善，却仍未达到全测试通过。

## 结论边界

TACO-100 只用于轨迹诊断和候选缩小，不能代替 TACO-515 的最终 checkpoint 比较，也不能单独决定 GRPO 起点。

# EXP-023：TACO-515 冻结严格执行评测

**日期**：2026-08-05  
**类型**：实验 / 主 SFT 代码能力证据  
**评测集**：冻结 TACO-515，其中 `standard_input=393`、`call_based=122`。

## 严格 Pass@1

| 模型 | Overall | Standard | Call | 平均测试通过率 | 平均生成 tokens |
|---|---:|---:|---:|---:|---:|
| Base | 80/515 = 15.53% | 17/393 = 4.33% | 63/122 = 51.64% | 21.50% | 506.87 |
| LR 2e-4 step50 | 120/515 = 23.30% | 61/393 = 15.52% | 59/122 = 48.36% | 36.15% | 627.10 |
| LR 1e-4 step20 | 113/515 = 21.94% | 49/393 = 12.47% | 64/122 = 52.46% | 33.01% | 672.11 |
| LR 1e-4 step200 | 128/515 = 24.85% | 71/393 = 18.07% | 57/122 = 46.72% | 37.35% | 626.90 |

## step200 相对 Base

- Overall：增加 48 题，提升 9.32 个百分点，相对提升约 60%。
- Standard：增加 54 题，从 4.33% 提升到 18.07%，约为 Base 的 4.18 倍。
- Call：减少 6 题，从 51.64% 降到 46.72%。
- 平均测试通过率：从 21.50% 提升到 37.35%。

## step20 的作用

step20 不是最高 Overall checkpoint，但它提供了重要的“能力保持型”对照：

- Standard 从 17/393 提升到 49/393；
- Call 从 63/122 微升到 64/122；
- Overall 从 80/515 提升到 113/515。

因此 step20 不能仅因 Overall 低于 step200 而删除。它用于区分：

```text
step200 的 Call 下降
是 TACO 小样本波动
还是训练后期的外部函数补全能力遗忘
```

## 不确定性边界

粗略 Wilson 区间显示：

- Overall：Base 约 12.66%–18.92%，step200 约 21.32%–28.76%；
- Standard：Base 约 2.72%–6.82%，step200 约 14.58%–22.17%；
- Call：Base 约 42.86%–60.32%，step200 约 38.10%–55.54%。

前两项区间不重叠，Call 区间重叠。但这些是独立比例近似，不是配对显著性检验。正式报告仍需基于逐题结果执行：

- 配对 McNemar 检验；
- 配对 bootstrap；
- 多 checkpoint 比较时进行 Holm 校正。

**状态**：严格结果已验证；配对显著性统计待补。

# EXP-024：文本 I/O 路由器的标签泄漏审计

**日期**：2026-08-05  
**类型**：实验 / 负结果 / 数据泄漏审计

## 初始结果

基于 TF-IDF 词/字符 n-gram 与类别平衡逻辑回归的文本路由器，在 TACO-515 上得到：

```text
accuracy = 1.0
macro-F1 = 1.0
confusion matrix = [[393, 0], [0, 122]]
```

该结果最初看似证明可由题面文本完美判断 `standard_input` 与 `call_based`。

## 泄漏证据

审计结果：

- `forbidden_literal_scan.passed = false`；
- 发现 41,224 次显式标签字面量命中；
- 最高权重特征直接包括：
  - `io_mode standard_input`；
  - `io_mode call_based`；
  - `standard_input`；
  - `call_based`；
  - `fn_name 无`。
- 当前 SFT user prompt 尾部人为追加了：

```text
【判题接口】
- io_mode: ...
- fn_name: ...
【starter_code】
...
```

这不是 TACO 原始 `question` 的自然题面，而是 CodeGuide 构造阶段注入的元数据。

仅屏蔽部分常见接口提示后准确率仍为 1.0，原因是显式标签和其他强代理字段仍然存在，而不是模型真正学会了自然题面接口推断。

## 结论

当前 100% 文本路由准确率无效，不得进入报告、简历或部署声明。

该泄漏只影响路由器实验，不影响：

- SFT 训练是否完成；
- TACO-515 代码生成结果；
- Base/step20/step200 checkpoint 本身。

但它改变了 TACO-515 的解释边界：当前评测属于“已知金标准接口标签下的代码生成”，不能等同于“模型只看自然题面自主判断接口”。

**状态**：负结果已验证；原路由方案退出主线。

# EXP-025：当前 TACO 提示词的接口标签暴露

**日期**：2026-08-05

当前 TACO-515 的 canonical user message保留了 CodeGuide 构造阶段追加的 `io_mode`、`fn_name` 与 `starter_code`。评测脚本会替换或补充 system prompt，但不会清除这些 user metadata。

因此当前主结果应准确表述为：

> 在给定判题接口元数据的冻结 TACO-515 上，Mixed QLoRA SFT 将严格 Pass@1 从 15.53% 提升到 24.85%。

不能表述为：

> 模型只根据自然语言题面自主判断接口并取得 24.85%。

后续新增一个独立的 clean-interface track：

- 删除人工追加的 `io_mode` 与 `fn_name` 标签；
- 保留题目原始自然语言；
- 原生非空 starter code/signature 可保留，因为它是题目本身的一部分；
- verifier 仍持有真实模式，但不向模型泄漏；
- 先在 TACO-100 做提示词小消融，再决定是否扩展到 515。

该 clean track 不覆盖现有 515 结果，而是作为额外泛化评测。

# DEC-036：代码能力与教学能力分模块评估

**日期**：2026-08-05

## 代码能力模块

主要指标：

- 严格 Pass@1；
- 平均测试通过率；
- Standard/Call 分模式结果；
- 接口匹配；
- 语法失败；
- 生成上限命中；
- HumanEval(+)、MBPP(+) 外源结果。

## 教学能力模块

现有 `template_complete` 只检查栏目字符串是否出现，不能证明讲解正确或有教学价值。正式教学评测需要两层：

### 全量客观格式审计

对 Base、step20、step200 的已保存 TACO-515 generation 统计：

- Python 代码块是否位于开头；
- 是否恰好一个 Python 代码块；
- 题意、关键观察、步骤、复杂度、常见错误是否齐全；
- 栏目顺序是否正确；
- 每个栏目是否非空或过短；
- 第二代码块、伪代码、示例调用等合同违例；
- 截断率、平均章节长度和总长度。

### 冻结 TACO-100 教学盲评

匿名比较 Base、step20、step200，维度包括：

- 题意理解准确性；
- 关键观察的正确性与有效性；
- 步骤清晰度；
- 讲解与代码一致性；
- 复杂度正确性；
- 常见错误的实用性；
- 初学者友好度；
- 简洁性与无冗余。

同时报告：

1. 全样本综合教学效用；
2. 双方代码都严格通过的交集，用于尽量隔离纯教学质量。

项目最终主张应以教学能力为核心，代码提升作为不可缺少的正确性基础，而不是把 CodeGuide 叙述成普通代码生成微调。

# INC-005：EvalPlus 云端启动脚本局部变量未绑定

**日期**：2026-08-05

## 现象

```text
scripts/run_evalplus_code_capability_cloud.sh: line 48: variant: unbound variable
```

## 根因

在开启 `set -u` 后，同一条 `local` 语句一边给 `variant` 赋值，一边使用 `${variant}` 构造日志路径；Bash 展开时变量尚未完成赋值。

## 修复

将变量声明拆成三行：

```bash
local gpu="$1"
local variant="$2"
local log="$OUTPUT_ROOT/logs/generate_${variant}.log"
```

错误发生在任何模型 generation 之前，没有产生样本或 benchmark 结果。

**状态**：已修复。

# DEC-038：GRPO 进入门槛

**日期**：2026-08-05

找到 TACO 最高 checkpoint 不等于可以直接启动正式 GRPO。进入 GRPO 前需满足：

```text
[ ] 唯一 Mixed SFT_CHAMPION 已冻结
[ ] EvalPlus Base/step20/step200 结果齐全
[ ] SFT 教学客观格式基线已落盘

[ ] 16～32 题、20～50 steps 的 GRPO smoke 通过
```

GRPO smoke 至少确认：

- 正确代码的执行奖励最高；
- 代码错误不能靠教学栏目完整获得更高总奖励；
- 组内奖励长期不应全部相同；
- 没有迅速退化为固定模板、超长讲解或无代码输出；
- adapter、optimizer、checkpoint 和 held-out 评测链路都能保存与恢复。

双专家 Oracle、分类器和完整 LiveCodeBench 不作为正式 GRPO 的硬阻塞项；它们可以并行或后补。
